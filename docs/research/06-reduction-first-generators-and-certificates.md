# 06 — Reduction before grouping, generator borders, bounded explanations

**Scope.** Three questions about the one-dimensional solver: does reducing
the border set *before* building groups help; what does the fallback
construction of contradiction explanations cost in the worst case; and how
are answers certified to a separate checker. Status labels as in note 01.
"Tested" refers to the 54 self-tests of `prefsuf.rs`, to `reduce_lab.rs`
and to `cert_lab.rs`. Machine as in note 04; all timings are single runs.

Notation as in note 01: text length n, Border rules with borders b (shift
n − b), m of them. A **phase** is a maximal run of grouping rounds with the
same shift p; phase i starts at text length Lᵢ, has shift pᵢ and Tᵢ rounds,
and ends at Lᵢ₊₁ = Lᵢ − Tᵢpᵢ. Its border Lᵢ − pᵢ is either a Border rule
of the puzzle (a **rule phase**) or the border Lⱼ₊₁ − pⱼ left behind by an
earlier phase j (a **derived phase**). This is exactly the bookkeeping of
`Derivation::new` in `prefsuf.rs`.

## 1. The reduction needs no array (Proved here, Tested)

The phases depend only on the border lengths. A run of rounds with the same
shift ends when the next border L − p drops below the longest border still
waiting, w; the number of rounds is one division, ⌊(L − w − 1)/p⌋.
`reduction_phases` computes the list of phases this way, in
O((m + R) log m) time for R phases, without touching any position.

From the phases alone:

- **the number of groups**: what is left after the last phase, plus the
  positions each phase leaves unlinked (`groups_from_phases`);
- **the group of any one position**, in O(R) arithmetic (`root_query` in
  `reduce_lab.rs`): step down by p inside each phase by division.

So the partition has a description of size O(R), where R is bounded next.

## 2. At most 2 log₂ n + 2 phases (Proved here, Tested)

**Theorem 16.** The shifts of consecutive phases satisfy pᵢ₊₁ < pᵢ and
pᵢ₊₂ < pᵢ / 2. Hence there are at most 2 log₂ n + 2 phases, whatever the
number of borders.

*Proof.* Let W be the borders waiting when phase i starts, k = max W,
pᵢ = Lᵢ − k, and let w be the longest waiting border when phase i ends.
Phase i ends either because Lᵢ₊₁ ≤ pᵢ, or because its next border
c = Lᵢ₊₁ − pᵢ is smaller than w (then c joins the waiting borders).

*pᵢ₊₁ < pᵢ.* Phase i+1 uses the border w, so pᵢ₊₁ = Lᵢ₊₁ − w. In the first
case pᵢ₊₁ < Lᵢ₊₁ ≤ pᵢ; in the second w > c gives
pᵢ₊₁ < Lᵢ₊₁ − c = pᵢ.

*pᵢ₊₂ ≤ pᵢ − pᵢ₊₁ or pᵢ₊₁ ≤ pᵢ/2.* Phase i+1 has at least one round, so
Lᵢ₊₂ ≤ Lᵢ₊₁ − pᵢ₊₁ = w. If phase i ended with Lᵢ₊₁ ≤ pᵢ, then
pᵢ₊₂ < Lᵢ₊₂ ≤ w = Lᵢ₊₁ − pᵢ₊₁ ≤ pᵢ − pᵢ₊₁. Otherwise c is waiting during
phase i+1, whose rounds continue only while the next border is at least
every waiting border, so Lᵢ₊₂ ≥ c. If Lᵢ₊₂ > c, phase i+2 uses a border
k″ ≥ c and pᵢ₊₂ = Lᵢ₊₂ − k″ ≤ w − c = pᵢ − pᵢ₊₁. If Lᵢ₊₂ = c, then
Tᵢ₊₁pᵢ₊₁ = Lᵢ₊₁ − c = pᵢ with Tᵢ₊₁ ≥ 2 (because pᵢ₊₁ < pᵢ), so
pᵢ₊₁ ≤ pᵢ/2.

In every case pᵢ₊₂ < pᵢ₊₁ and (pᵢ₊₂ ≤ pᵢ − pᵢ₊₁ or pᵢ₊₁ ≤ pᵢ/2), which
gives pᵢ₊₂ < pᵢ/2. Since p₀ < n and every shift is at least 1, a phase with
index 2j exists only if 2ʲ < n. ∎

This is the bound for Euclid's algorithm, for the same reason. Tested: the
bound holds on 34,000 random border sets (self-tests and `reduce_lab.rs`);
the most phases seen were 14 in the tables below and 22 (bound 40) in a
hill-climbing search at n = 1,000,000.

## 3. Generator borders (Proved here, Tested)

Call the Border rules that start a rule phase the **generators**. By
Theorem 16 there are at most 2 log₂ n + 2 of them.

**Theorem 17.** The links of the generator rules alone force every equality
that all the Border rules force. Equivalently: union-find over the links of
the generators gives exactly the groups.

*Proof.* Let ≈ be the equivalence generated by all links of the generator
rules. Every generator link is a link of the puzzle, so ≈ is contained in
the true grouping. For the converse it is enough to show that every link
written by the grouping rounds is in ≈, because those links generate the
true grouping (Theorem 1 of note 01). Write dᵢ = n − Lᵢ. By induction on i
we prove

- **Iᵢ:** j ≈ j + dᵢ for every j < Lᵢ (the first Lᵢ characters are a
  border of the text), and
- **Qᵢ:** y ≈ y + pᵢ for every y < Lᵢ − pᵢ (they repeat with shift pᵢ).

I₀ is trivial. *Qᵢ for a rule phase* with rule border b = Lᵢ − pᵢ: for
y < b, y ≈ y + (n − b) is a generator link, and n − b = pᵢ + dᵢ, so
y + (n − b) = (y + pᵢ) + dᵢ ≈ y + pᵢ by Iᵢ (as y + pᵢ < Lᵢ).
*Qᵢ for a derived phase* whose border b = Lⱼ₊₁ − pⱼ was left by phase
j < i: put e = Lⱼ₊₁ − Lᵢ ≥ 0, so pᵢ = pⱼ − e. For t < Lᵢ, Iᵢ and Iⱼ₊₁ give
t ≈ t + dᵢ = (t + e) + dⱼ₊₁ ≈ t + e. For y < b: y ≈ y + pⱼ by Qⱼ (as
y + pⱼ < Lⱼ₊₁), and with t = y + pᵢ < Lᵢ, y + pᵢ ≈ y + pᵢ + e = y + pⱼ.
*Iᵢ₊₁ from Iᵢ and Qᵢ:* for j < Lᵢ₊₁, Qᵢ applied Tᵢ times gives
j ≈ j + Tᵢpᵢ (each step starts below Lᵢ − pᵢ), and Iᵢ gives
j + Tᵢpᵢ ≈ j + Tᵢpᵢ + dᵢ = j + dᵢ₊₁.

A link written in phase i joins j − pᵢ and j for some j < Lᵢ; that is Qᵢ. ∎

So only O(log n) of possibly millions of borders carry information; every
other Border rule is a consequence of them. Tested on 34,000 random border
sets and 14 named shapes at four sizes: union-find over generator links
equals the grouping, and the resulting forest has exactly n − (groups)
links. The largest number of generators seen was 5.

most n). Links looked at: naive, all of them; generators, at most n per

15.3 MB, naive and generators 7.6 MB, phases only: the border list plus 40
bytes per phase. Forest size (the certificate) is n − groups for every
strategy.

**Conclusions.**

- **For building the groups, reduction-first is not faster.** The current
  grouping already *is* the reduction (note 01, section 4); "labels" does
  the same writes in a different order and lands within noise of it.
  `equal_positions` was therefore left unchanged.
- **For counting, reduction-first wins by orders of magnitude** when there
  are few borders (microseconds, no array), and is limited by sorting the
  borders when there are millions.
- **For certificates, reduction-first is what makes the cost provable:**
  the forest comes from union-find over at most (2 log₂ n + 2)·n links.
- **In more than one dimension** the corresponding comparison is in note 05,
  section 8: reduce-then-count is exact and takes microseconds when the core
  has at most two shifts, and falls back to union-find on the core
  otherwise. Runs of equal reduction steps are done by one division there
  too (`reduce_chain` in `grid_lab.rs`; the released points telescope to
  a₀ − a₁ − a_t + a_{t+1}, with a_s the volume of the box shrunk s times):
  an interval of 8,000,000 with shifts 3 and 5 went from 0.89 s
  (7,999,996 single steps) to 13 µs (4 divisions).

**Priority among reduction steps.** In one dimension the order is forced
(longest border first; Theorem 1 needs the smallest shift). In boxes the
dominated shift is unique (note 05, Proposition 12). So no correct
alternative ordering exists within the proved theorems; the only freedom is
in steps that are exact without being dominated, which is a heuristic
(note 05, section 4).

## 5. The cost of explanations (Proved here; Measured)

When a puzzle is contradictory the solver shows a chain of links between
two clashing positions. `explain` in `prefsuf.rs` now proceeds as follows:

1. breadth-first search over all borders: the shortest chain, abandoned
   after a fixed budget of 2·10⁸ + 32n link tests;
2. **new:** breadth-first search over the generator borders only
   (`generator_path`), then cheap shortening;
3. the earlier recursive derivation (`derive_path`), kept as a further
   fallback. By Theorem 17 step 2 always succeeds for positions of one
   group, so step 3 is not expected to run.

**Theorem 18 (cost of step 2).** `generator_path` finds a chain whenever
the two positions are forced equal, the chain is the shortest one that uses
generator links only, and the search tests at most 2gn ≤ (4 log₂ n + 4)·n
links, g being the number of generators. Shortening costs at most
8L + 64 look-ups for a chain of L positions plus a table of size n.

*Proof.* Existence is Theorem 17; breadth-first search returns a shortest
path; each of at most n positions is expanded once and tries each of the g
shifts in both directions. ∎

So the whole explanation costs O(2·10⁸ + n log n) link tests in the worst
case. Previously the fallback's cost was only measured.

**What is still only measured.** The cost of the earlier derivation
(`derive_path`) remains unproved; it is no longer on the main path.
Theorem 16 does bound its recursion depth by 2 log₂ n + 2, which was open.

**What is not claimed.** Chains from step 2 are valid, not shortest overall.
Whether shortest chains can be found in subquadratic time in general is
still open.

it varies between 0.014 s and 0.163 s per million with g between 2 and 4.

## 6. Certificates (`--certificate`, `certcheck.rs`)

Format and verification rules: `docs/certificate-format.md`. The solvable
certificate's forest is the union-find forest over generator links, so it
costs O(n log n · α(n)) to produce (Theorem 17); the checker is independent
of that theorem — it only tests the links, counts groups and checks the
borders of the label sequence.

Tested (`sh cert_lab.rs check 1`):

- 20,000 random puzzles (15,913 solvable, 4,087 contradictory): every
  certificate accepted, every verdict true; for short texts the stated
  number of texts equals the number found by listing all texts.
- 196,108 randomly damaged certificates (numbers changed, lines deleted,
  duplicated or swapped, truncation, text appended, single bytes changed):
  none accepted with a false statement; 975 harmless changes accepted; no
  crash.
- 26,776 deliberate forgeries (two groups merged, with and without a
  forged link; a group split; a link removed; wrong free count; all
  positions separate; invented contradictions): none accepted with a false
  statement.
- 22 malformed files and 10 boundary puzzles (length 0 and 1, B0, Bn,
  empty words, one letter, 94 letters, every border, repeated rules).

At n = 5,000,000 (`sh cert_lab.rs big`):

## 8. Open

1. A bound on the number of *generators* better than the number of phases
   (at most 5 were ever seen).
2. Short chains: is there a provably near-shortest chain in near-linear
   time? The small-periods shape is the test case.
3. Whether Theorems 16 and 17 are in the literature on multiperiodic words
   (they look like natural companions of Holub's algorithm; no search was
   made beyond the sources of note 04).
4. A machine-checked proof of Theorems 1, 16, 17 and of the checker.
